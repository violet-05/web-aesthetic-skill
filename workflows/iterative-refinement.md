# 迭代修复工作流

## 基线
保留第一次 JSON、HTML、截图、配置与代码状态。按 P0 → P1 → P2 → P3 排序；对启发式意见先判断设计意图。记录问题指纹、影响、建议、涉及文件和回归场景。

## 小范围修复
用户授权后，由 Agent 或开发者修改直接相关代码。核心工具只审查，不自动编辑。禁止删除测试、放宽预期、隐藏内容或升级无关依赖来制造通过。重要变更先保留差异；失败时说明原因，不无限尝试。

## 再验证
用相同 URL、视口、场景和等待条件重新执行。运行 compare --before old/report.json --after new/report.json --iteration 1。它区分 fixed、remaining、added、unverified、regressions；缺失或未知的规则不能算已修复。

## 停止
默认最大 3 轮，通过 maxIterations 配置调整。达到上限必须停止并列出剩余问题；自动门槛清除且核心交互/布局通过可提前停止。工具输出 stopReason 只是建议，不是代码修复控制器。视觉审美仍需查看前后截图，不存在自动像素差或主观分数保证。

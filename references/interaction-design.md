# 交互设计规范

## 状态契约
为每个控件写下输入、动作、等待、结果、失败与恢复。立即反馈操作被接收，较长任务显示进度或说明；失败要保留数据并允许重试。状态不是视觉装饰，必须由真实逻辑驱动。只对实际存在的状态实现样式。

## 常见组件

### Button 与 Link
按钮触发动作，链接表达可导航目的地。文本说明动作或目标；危险操作使用额外上下文或确认。Hover 只是辅助，focus-visible、active、disabled、loading 状态按任务存在。加载期间防重复提交但保留失败恢复。外链或下载行为要提前说明。

### Navigation 与 Dropdown
明确当前位置和菜单层级。折叠菜单有展开状态、可访问名称和关闭途径。不要让触摸端只靠 hover。菜单打开后能用键盘移动或自然 Tab 浏览，Esc 关闭后返回触发按钮。复杂应用菜单遵循适当 ARIA 模式，不盲目给普通链接列表加 menu 角色。

### Modal
标题与 dialog 关联。打开后焦点进入，背景不接受交互，Esc 与可见按钮可关闭，关闭后恢复焦点。破坏性确认突出后果，不能通过误触遮罩执行危险动作。检查移动端内容滚动、虚拟键盘和焦点不被遮挡。

### Tabs 与 Accordion
Tab 表示同一区域的不同面板，选择状态与可见面板一致；按相应模式实现方向键和焦点。Accordion 的控制按钮报告 expanded，面板展开不应丢失滚动位置。可用原生 details/summary 满足简单场景。

### Form 与 Input
标签持续可见，不以 placeholder 替代。选择匹配的数据类型、自动填充与输入方式。错误在合适时机出现，说明如何修复并关联字段；保留输入。成功反馈可感知，服务失败不伪装成功。测试无效输入、重复提交、失败恢复与禁用状态。

### Search
说明搜索范围、提交时机、加载状态与空结果；实时搜索应处理旧请求覆盖新结果的竞争。清除查询可恢复默认视图。示例不接 API 时明确写“本地示例”，不可做装饰搜索框。

### Toast 与 Tooltip
Toast 用于非阻断反馈，重要错误不能只短暂闪现；必要时用 live region。Tooltip 只是补充信息，不承载唯一操作入口；键盘聚焦也可获得内容，Esc 可关闭。不要将 tooltip 当无标签按钮的补救。

### Pagination 与 Toggle
分页状态与 URL/数据一致，边界页禁用合适按钮并解释范围；切页后保留合理焦点。Toggle 明确开关对象与当前状态，设置失败需要回滚与提示，不能只变颜色。

### Loading Indicator
短等待可即时响应，较长等待需要文字或进度。避免无期限旋转且无取消/重试。骨架与真实布局相近以减少跳动；减少运动时保留状态文本。

## 可执行场景
每个关键任务有前置条件、明确动作、结果断言和清理。优先 role/name、label、testId 定位，CSS 作为受控后备。仅点击后不抛异常不算功能通过；必须断言文本、可见性、焦点、值或 URL。对于无法推断的业务结果标记待人工检查。

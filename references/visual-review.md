# 基于真实截图的视觉评审

## 输入
先确认截图来自本轮运行、指定 URL 与视口，而不是设计稿或旧图片。读取报告的导航状态、截图 phase、截断标记与诊断。若页面被资源策略阻止，先说明渲染条件，不把缺字体直接判为产品设计缺陷。

## 观察顺序
先判断核心任务与信息入口，再看区块关系、标题断行、对齐、间距、色彩层级、图片主体和内容密度。随后比较手机与桌面，最后检查细节。对动效、hover、焦点和提交结果必须观察实际状态，不能从静态截图猜测。

## 证据语法
用“截图/视口/区域 → 可观察现象 → 对用户任务的影响 → 建议”记录意见。例如手机首屏的说明段压过主标题与操作，应缩短说明并降低其视觉重量。这是 manual 或 ai 意见，不是 measured 事实。

## 不确定与反证
异形对齐、低密度、强烈颜色或夸张字体可能是有意风格。结合品牌、受众和任务判断；缺上下文时标记未知。不要因页面不符合个人偏好就全部重写。

## 输出
每项意见给优先级、截图路径和最小修复方向。修复后保留相同尺寸的前后截图，再跑交互。没有视觉查看能力时明确未执行此步骤；没有模型时不生成貌似精确的美学分数。

# 设计原则与决策记录

## 从任务而不是装饰开始
确定用户来到页面要做的第一件事、阻止他们完成任务的因素，以及业务希望建立的认知。产品官网重在理解与信任，后台重在比较与操作，作品集重在作品与作者判断。视觉选择必须解释它服务了什么目标。

## 约束与优先级
先记录已有品牌、内容长度、设备范围、技术栈、加载预算与无障碍要求。排序为可用性与内容正确性 → 清晰与可读性 → 风格一致性 → 个性表达 → 微观润色。不是说个性不重要，而是不能用风格掩盖失败操作。

## 决策方法
给关键选择写“选择 / 原因 / 代价 / 验证”。例如宽标题建立阅读入口，但长中文标题可能占满移动首屏；应在真实内容下检查断行，而非固定三个示例词。比较两个方向时使用同一内容和任务，避免被更好的文案误导。

## 一致与变化
一致性是相同意义使用相同表达，不是所有区块长得一样。主要动作共享视觉权重，危险动作共享语义；叙事区块可根据内容改变构图。不要将全部内容压进卡片来获得表面统一。

## 交付证据
设计说明应能连接到实际页面、Token、状态和截图。若用户只要建议，提供选择与验证方式即可；不要用“全面升级”扩展授权。
